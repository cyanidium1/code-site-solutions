## Фаза 1 — неделя 1. Дешёвые правки с непропорциональным эффектом

### 1.1 Вернуть кэширование отраслевым страницам · ~1 час

Три файла: `src/app/(uk)/sites-for/[slug]/page.tsx`, `(en)/en/...`, `(ru)/ru/...`

Добавить по образцу `portfolio/[slug]/page.tsx`:

```ts
export const dynamicParams = true;
export const revalidate = 3600;

export async function generateStaticParams() {
  // вернуть список слагов отраслевых страниц из Sanity
}
```

**Проверка результата:** `curl -sI https://www.code-site.art/sites-for/legal | grep -i vercel-cache`
должен показать `HIT` вместо `MISS`, а `X-Nextjs-Prerender: 1` — появиться.
TTFB должен упасть с ~0.43 с до ~0.15 с.

**Как понять, что не сработало:** если после деплоя заголовок остался `MISS`, значит
динамический рендер вызывает что-то внутри дерева компонентов — искать `cookies()`,
`headers()`, `searchParams` или `noStore()` в `industry-page/`.

### 1.2 Починить мобильный первый экран · ~2 часа

Две правки, обе в вёрстке главной:
- Высота hero-иллюстрации на мобильных брейкпоинтах → примерно 40–45vh
- Cookie-панель → тонкая нижняя плашка вместо блока на треть экрана

**Проверка:** скриншот 375×812 должен содержать H1 и минимум одну CTA-кнопку без скролла.
Параллельно перемерить CLS — гипотеза, что 0.27 даёт именно cookie-панель.

### 1.3 Исправить `Review.itemReviewed` · ~30 минут

`case-page/index.tsx`, функция `buildCaseJsonLd()`: заменить ссылку на `#article`
на `ORG_ID`. В `industry-page/index.tsx` это уже сделано верно — взять оттуда.
Затрагивает 78 страниц кейсов одной правкой.

### 1.4 Добавить `Article.image` · ~1 час

Там же: заполнить обязательное поле из `doc.hero.heroImage`, обернув в `sanityCdn`
по правилам `docs/images.md`.

### 1.5 Убрать `HowTo` с `/process` · ~15 минут

Rich-результат снят в 2023. Удалить узел из билдера JSON-LD, вёрстку не трогать.

### 1.6 Заголовки безопасности · ~30 минут

Блок `headers()` в `next.config.ts`, минимум:
`X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`,
`X-Frame-Options: SAMEORIGIN`. HSTS дополнить `includeSubDomains`.

## Фаза 4 — постоянно. Измеримость

Сейчас главная проблема аудита не в находках, а в том, что половину вопросов
измерить нечем.

### 4.1 Подключить Google API · ~1 час, бесплатно

Даст полевые Core Web Vitals вместо лабораторных, реальную индексацию, показы и клики.
Конфиг: `~/.config/claude-seo/google-api.json`. Минимум — API-ключ для PageSpeed,
дальше OAuth для Search Console и GA4.

После подключения перемерить CLS 0.27 на полевых данных — лабораторный замер может
как преувеличивать, так и преуменьшать.

### 4.2 Подключить Moz API · ~15 минут, бесплатно

2 500 строк в месяц. Переводит ссылочный профиль из «данных нет» в измеримое состояние.

### 4.3 Снять базлайн дрейфа

`drift_baseline.py` по ключевым URL — после этого каждый деплой можно проверять на
незамеченные регрессии в title, description, canonical, разметке.

### 4.4 Проверить незалинкованные упоминания бренда

Автоматические запросы к поисковикам заблокированы. Нужен ручной поиск по
`"code-site.art"`, `"Code-Site.Art"`, `"Code-Site" студия -site:code-site.art`.
Упоминание без ссылки — самый дешёвый источник ссылки.

## Что сознательно не делать

- **Не удалять `FAQPage` со 119 страниц прямо сейчас.** Rich-результат снят, но штрафа нет,
  контент виден на странице, разметка ему соответствует. Просто перестать её генерировать
  при следующей переработке шаблонов.
- **Не добавлять `AggregateRating`,** пока нет внешнего источника рейтинга. В коде уже
  стоит TODO с ожиданием Google Business Profile — это верное решение, не трогать.
- **Не вкладываться в `llms.txt` ради Google.** Google официально его не использует.
  Обновить до трёх локалей стоит, потому что файл уже есть, но эффекта на выдачу не ждать.
- **Не пытаться обогнать Clutch и DesignRush** по головному английскому запросу.
  Директории занимают выдачу структурно. Дешевле попасть в их листинги.
- **Не убирать `priority` и `changefreq`** из карт ради самого факта — Google их
  игнорирует, но вреда от них нет.
