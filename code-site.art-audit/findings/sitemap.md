# Sitemap Architecture — code-site.art

Проверено: `sitemap-index.xml` + 3 дочерние карты (`sitemap-ua.xml` 73 URL, `sitemap-en.xml` 71 URL,
`sitemap-ru.xml` 64 URL), сверка с живым сайтом через `curl` (208/208 URL из карт, статус-коды с
редиректами и без).

## 1. Валидность XML / протокол sitemaps.org

- Все 4 файла — валидный, хорошо сформированный XML (корректные открывающие/закрывающие теги,
  один `<?xml version="1.0" encoding="UTF-8"?>` + `<?xml-stylesheet ... href="/sitemap.xsl"?>`).
- `sitemap-index.xml`: `<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">`, 3 записи
  `<sitemap><loc>…</loc><lastmod>…</lastmod></sitemap>` — корректно.
- Дочерние карты: `<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"
  xmlns:xhtml="http://www.w3.org/1999/xhtml">` — оба неймспейса объявлены правильно, xhtml нужен
  именно для `xhtml:link` (hreflang) и присутствует.
- Каждый `<url>` содержит `<loc>` с абсолютным `https://www.code-site.art/...` — протоколу
  соответствует.
- Лимиты: ua 73 URL / 43 КБ, en 71 / 43 КБ, ru 64 / 40 КБ — на три порядка ниже лимита 50 000 URL /
  50 МБ. `news:`-карт нет, ограничение 1000 URL неприменимо. **Разбиение на 50k не требуется.**

## 2. HTTP-статусы всех 208 URL из карт

Прогнал `curl` по каждому URL из `all-urls.txt` дважды: без follow-redirect
(`--max-redirs 0`) и с follow. **208/208 URL вернули `200 OK` напрямую, без единого редиректа.**
Редиректов, 404 и явных дублей внутри карт не найдено.

## 3. `<lastmod>`: кто без него и почему

Подтверждено: ua 55/73, en 56/71, ru 54/64 URL имеют `<lastmod>`. Разница объясняется
**одной закономерностью, не случайностью**: `lastmod` отсутствует ровно у статических
навигационных/маркетинговых страниц (не из CMS), и присутствует у всех страниц, приходящих из
Sanity (портфолио, блог, sites-for-индустрии).

| Локаль | URL без `lastmod` | Причина |
|---|---|---|
| ua (18 без lastmod) | `/`, `/about`, `/process`, `/pricing`, `/portfolio`, `/contacts`, `/blog`, `/calculator`, `/landing`, `/corporate-site`, `/online-store`, `/seo`, `/support`, `/vs-wordpress`, `/vs-constructors`, `/vs-freelancers`, `/sites-for/medicine/stomatolohiia`, `/sites-for/medicine/medychnyi-tsentr` | статические App Router страницы + 2 под-страницы медицины без даты |
| en (15 без lastmod) | те же 12 статических корневых (кроме `/support`, которого в en нет) + `/en/vs-wordpress`, `/en/vs-constructors`, `/en/vs-freelancers` | то же самое, но `/en/support` не существует |
| ru (10 без lastmod) | `/ru`, `/ru/process`, `/ru/portfolio`, `/ru/contacts`, `/ru/blog`, `/ru/calculator`, `/ru/landing`, `/ru/corporate-site`, `/ru/online-store`, `/ru/seo` | в ru нет about/pricing/vs-*/support вообще (см. §4) |

Арифметика сходится 1:1 (73−18=55, 71−15=56, 64−10=54), т.е. это не шум — генератор карты просто
не проставляет `lastmod` статическим страницам.

### Правдоподобность дат у страниц, где `lastmod` есть

- **`sites-for/*` (8 индустрий) — у всех трёх локалей абсолютно идентичный `lastmod`:
  `2026-08-22T13:44:44.000Z`**, без единой секунды расхождения между medicine/renovation/legal/
  finance/ecommerce/auto/real-estate/courses и между локалями. Это не «последнее значимое
  изменение», это штамп массового redeploy/ре-публикации.
- **`portfolio/*` (25 кейсов)** — кластеризуются в 3 значения: `11:02:17` (18 кейсов), `11:02:28`
  (3 кейса: raul-avto, mono-pools, e-fedra-beauty), и одно исключение `icelab` = `14:18:05`.
  `14:18:05` **совпадает секунда-в-секунду** с `<lastmod>` всех трёх записей в `sitemap-index.xml`
  (build-время генерации карты) — то есть для icelab дата взята из момента сборки карты, а не из
  реального редактирования в CMS.
- **`blog/*`** — кластер `11:02:44` (большинство постов), несколько на `11:02:17`,
  `11:02:57`, `13:21:19`, и два поста (ai-search, seo-audit) — `09:59:50`/`09:59:59` (16 авг., на
  неделю раньше остальных — единственные правдоподобно «настоящие» даты в выборке).

**Вывод:** `lastmod` в целом технически валиден (W3C datetime, ISO 8601 с `Z`), но подавляющее
большинство значений — это временные метки batch-редеплоя/миграции CMS, а не даты реального
последнего значимого изменения контента. Google, скорее всего, уже игнорирует этот сигнал для
данного домена (кластеризация слишком очевидна). Отсутствие `lastmod` у самых важных конверсионных
страниц (`/pricing`, `/about`, `/contacts`) — отдельная проблема: там нет вообще никакого сигнала
свежести.

## 5. hreflang (`xhtml:link`) — полнота и взаимность

Суммарно 271 (ua) / 271 (en) / 256 (ru) = 798 записей `xhtml:link`. Реконструкция по типам URL
даёт точное совпадение (проверено построчным `sed`/`grep`, см. расчёт ниже) — то есть карты
внутренне согласованы, расхождение не случайное:

| Тип блока hreflang | Кол-во «концептуальных» страниц | Локалей на страницу | URL всего | Записей `xhtml:link` |
|---|---|---|---|---|
| Полный блок (uk+en-GB+ru+x-default, 4 записи) | 64 (home + 9 общих корней + 8 sites-for + 25 portfolio + 21 общий блог-пост) | 3 | 192 | 768 |
| Частичный блок (uk+en-GB+x-default, **без ru**, 3 записи) | 5 (about, pricing, vs-wordpress, vs-constructors, vs-freelancers) | 2 (ua+en) | 10 | 30 |
| Блок отсутствует полностью (0 записей) | 6 (support-ua, 2×sites-for/medicine/*-ua, 1×blog-ua-only, 2×blog-en-only) | 1 | 6 | 0 |
| **Итого** | | | **208** | **798** (271+271+256) |

Выводы:
- **Взаимность соблюдена** там, где перевод существует: каждая из 192 URL с полным блоком корректно
  ссылается на себя и на обе другие локали (проверено на всех прочитанных блоках — расхождений не
  найдено).
- **10 URL** (`about`, `pricing`, `vs-wordpress`, `vs-constructors`, `vs-freelancers` × ua/en) имеют
  «неполный», но **непротиворечивый** hreflang — ru не упомянут, потому что ru-версии не существует
  (подтверждено 404). Формально это не ошибка, но с точки зрения Google это сигнал «продолжай
  индексировать без ru-альтернативы», что стоит явно принять как решение, а не как дыру.
- **6 URL вообще без единого `xhtml:link`**, при этом соседние страницы того же типа (остальные 21
  блог-пост, остальные 8 sites-for) всегда имеют полный блок. Непоследовательность: генератор карты
  либо не знает, что делать с непереведённым контентом (пропускает hreflang целиком вместо
  self-referencing hreflang), либо это осознанное поведение для «одноязычных» лендингов — не
  задокументировано нигде в самой карте.

## 6. Мусор в картах

- Параметризованных URL (`?utm=`, `?page=` и т.п.) — не найдено.
- `priority`/`changefreq` — присутствуют на всех 208/208 URL без исключения (100% покрытие).
  Google оба тега официально игнорирует с 2020 г. — можно убрать, влияния на индексацию не окажет,
  но это лишний вес файла и повод для путаницы у тех, кто их всё ещё считает сигналом.
  `priority` при этом расставлен неровно (1.0 → 0.6), что дополнительно бесполезно.
- Дублей URL внутри карт не найдено (208 уникальных, как и заявлено в контексте).
- Редиректов и 404 внутри карт не найдено (см. §2 — 208/208 прямых `200`).
- `noindex`/`X-Robots-Tag`: точечная проверка заголовков ответа на 3 «подозрительных» URL
  (`/support`, `/en/blog/web-design-for-accountants`, `/ru/blog/skolko-stoit-sayt-2026`) —
  `X-Robots-Tag` не обнаружен, `200 OK` без noindex-заголовка. **Не проверено полностью** —
  `<meta name="robots">` в HTML-теле не сканировался по всем 208 URL из-за бюджета вызовов
  инструмента; для полного покрытия нужен отдельный прогон `parse_html.py` по каждому URL.

## 7. Покрытие / сироты

- `/stories/` (закрыт в `robots.txt`: `Disallow: /stories/`) — **не найден** ни в одной из трёх
  карт. Корректно, соответствие карты и robots.txt подтверждено. Сам путь при этом отдаёт `308`
  (редирект, не 404) — это нормально, важно только что его нет в sitemap.
- Полный обход внутренних ссылок с главной и из навигации на предмет страниц-сирот **не
  проводился** (нет бюджета вызовов на рендер + парсинг всех страниц) — эта часть проверки №6 не
  выполнена. Судя по составу карт (13 сервисных страниц, портфолио, блог, sites-for, vs-*), явных
  пропущенных разделов не видно, но это не эквивалент полного краула. Рекомендуется отдельный
  проход `render_page.py` + `parse_html.py` по хедеру/футеру/навигации для окончательного
  подтверждения отсутствия сирот.

## 8. Разумность разбиения по локалям

- При 208 URL суммарно всё уместилось бы в **один** файл `sitemap.xml` (лимит 50 000 URL) —
  разбиение по локалям сделано не из-за объёма, а, вероятно, ради независимой инвалидации кэша/ISR
  по языковым веткам. Это разумный инженерный выбор при работе с Next.js + Sanity, даже если сам
  по себе объём его не требует.
- Отдельные карты для блога/портфолио — **не нужны** ни сейчас (25 и 22–24 URL — далеко не 50k),
  ни в обозримой перспективе роста контента. Разделение по локали уже даёт достаточную гранулярность.

## 9. Location-page quality gate

Раздел `sites-for/*` — это отраслевые лендинги (medicine, renovation, legal, finance, ecommerce,
auto, real-estate, courses), не гео-локационные страницы. Порог 30+/50+ location-страниц из
skill-гайдлайна **не применим** — это не паттерн programmatic city-swap doorway pages. Оценка
уникальности контента (60%+) для этих 8 страниц не проводилась в рамках этого аудита sitemap (это
предмет content-аудита, не sitemap-архитектуры), но по масштабу (8 страниц) она в любом случае ниже
порога срабатывания gate.

## Что сделано правильно

- XML валиден во всех 4 файлах, оба неймспейса (`sitemaps.org/0.9` + `xhtml`) объявлены корректно.
- 208/208 URL из карт отдают чистый `200 OK` без единого редиректа — карта не содержит мусора,
  404 или цепочек редиректов.
- `/stories/` (закрыт в robots.txt) корректно отсутствует во всех трёх картах — согласованность с
  robots.txt подтверждена.
- Локальная асимметрия (`about`/`pricing`/`vs-*`/`support`/медицинские подстраницы/2 блог-поста)
  **не является багом генератора карты** — все отсутствующие URL реально не существуют на сайте
  (404 подтверждён `curl`), т.е. карта честно отражает реальный контент, а не «теряет» опубликованные
  страницы.
- hreflang полностью самосогласован: сумма 271+271+256=798 записей `xhtml:link` точно
  реконструируется из трёх типов блоков (полный/частичный/отсутствующий) без остатка — расхождений
  или битой взаимности не найдено там, где переводы существуют.
- portfolio (25/25/25) и sites-for (8/8/8, без учёта ua-эксклюзивных медицинских подстраниц)
  переведены на 100% на все три локали.
- Объём далеко не подходит к лимиту 50k/50MB — запас на порядки.

живому сайту), но два системных изъяна тянут балл вниз: (1) `lastmod` — там, где он есть, это в
основном штампы деплоя/миграции, а не реальные даты правок, и отсутствует у самых важных страниц
воронки; (2) `/pricing` и `/about` отсутствуют в ru — это не «асимметрия для галочки», а дыра в
конверсионной воронке для целого языкового сегмента.
