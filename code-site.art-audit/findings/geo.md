# GEO / AEO — готовність code-site.art к AI-поиску

Проверено вживую 2026-08-23 через `fetch_page.py`/`parse_html.py`/`agent_ux_check.py` и
точечно через WebFetch (для /seo, /vs-wordpress, 2 статей блога — параллельный агент
удалил мои промежуточные `geo-*.html` файлы из корня `code-site.art-audit`, поэтому по
этим страницам ниже приведены выводы без сырых файлов-доказательств; при необходимости
легко перепроверяется тем же способом). Главная и /pricing/process проверены напрямую
через сохранённый HTML и `parse_html.py`.

## 1. Доступ AI-краулеров (robots.txt) — подтверждено напрямую

`fetch_page.py https://www.code-site.art/robots.txt` → HTTP 200:

```
User-Agent: *
Allow: /
Disallow: /stories/

Host: https://www.code-site.art
Sitemap: https://www.code-site.art/sitemap.xml
```

Явных правил под конкретные UA (GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot,
anthropic-ai, CCBot, Google-Extended, Bytespider, Applebot-Extended) **нет** — работает
только блок `User-Agent: * / Allow: /`, который открывает доступ всем ботам по умолчанию.

Оценка компромисса (без догм):
- **Плюс:** все 4 «поисковых» AI-краулера (GPTBot, OAI-SearchBot, ClaudeBot,
  PerplexityBot) — не заблокированы. Для сайта, который на главной прямо обещает
  «ранжується в Google та AI-пошуку», это правильное базовое состояние: сам себе не
  противоречит.
- **Компромисс:** та же строка открывает и краулеры, тренирующие модели на контенте
  (CCBot, anthropic-ai, Bytespider), и `Google-Extended`. `Google-Extended` **не
  влияет на обычный органический Google Search** — он управляет только использованием
  контента для тренировки Gemini/AI Overviews моделей. Блокировка `Google-Extended` не
  снизит видимость в Google Search и Google AI Overviews; если владелец не хочет отдавать
  контент в тренировочные датасеты, это можно закрыть отдельной строкой без риска для SEO.
- Решение выглядит дефолтным (стандартный Next.js robots.txt), а не осознанно
  сформулированной AI-политикой — нет ни одной явной строки под конкретного бота.

## 2. Реальная выдача контента ботам без JS — подтверждено, тревога снята

`fetch_page.py` (чистый HTTP GET, без исполнения JS — так видят страницу боты, которые
не рендерят JS) на `https://www.code-site.art/`:
- Статус 200, полный HTML-ответ ~482 000 символов.
- Первый дочерний узел `<body>` — `<div hidden=""><!--$--><!--/$--></div>`. На первый
  взгляд похоже на пустую Suspense-заглушку React, но сразу следом в документе идёт
  **реальная, не скрытая разметка**: `<h1>`, `<p data-speakable="hero-description">` и
  т.д. с полным видимым текстом («Сайти будь-якої складності, що приводять заявки
  24/7...»). Это не признак пустой страницы — вероятно, скрытый div — отдельный
  портал/toast-контейнер, не основной контент.
- Подтверждённый факт: серверный HTML главной содержит **1530 слов / 9898 символов**
  видимого текста. Контент реально приходит краулерам без исполнения JavaScript.
- Скудная выдача trafilatura, зафиксированная в `_AUDIT-CONTEXT.md` (503 символа с
  главной) — это **артефакт алгоритма отсечения шаблонной обвязки (boilerplate)** самой
  trafilatura, а не признак тонкого контента или CSR-проблемы. Важно не путать одно с
  другим в клиентских отчётах.
- JSON-LD (`application/ld+json`) присутствует прямо в исходном HTML, доступен ботам без
  JS: `@graph` с Organization, WebSite, Person, Review, Rating, PostalAddress,
  ContactPoint, SpeakableSpecification, QuantitativeValue, ImageObject, Place, WebPage.
- `X-Nextjs-Prerender: 1` в заголовках — страница действительно prerendered/ISR, не CSR.
- Вывод: **дорогая находка из ТЗ не подтвердилась** — сайт не отдаёт ботам пустую
  страницу. Технически SSR работает как заявлено.

## 3. llms.txt — присутствует, качественно сделан, но без ru

`https://www.code-site.art/llms.txt` → HTTP 200, 7107 символов, валидный формат
(заголовок, описание студии на укр/англ, разделы `## Сторінки українською (/)`,
`## English pages (/en)`, `## AI resources`, `## Optional`).

Позитив:
- Раздел `## AI resources` указывает на **markdown-двойники ключевых страниц**:
  `/about.md`, `/faq.md`, `/pricing.md` (и англ. версии `/en/about.md`, `/en/faq.md`,
  `/en/pricing.md`) — все проверены, отдают HTTP 200 и чистый, разметочный markdown без
  навигационной обвязки. Это редкая, продуманная деталь, специально созданная под LLM.
- Пример содержимого `faq.md`: реальные Q&A-пары в формате `### Вопрос?` → прямой ответ
  первым предложением, с конкретикой (даты, цены, контакты, условия возврата). Пример:
  `### Чи є повернення коштів?` → «Передбачені випадки часткового повернення: якщо на
  етапі дизайну після двох повних раундів правок результат принципово не влаштовує
  замовника, повертається 70% передоплати...» — образцовый самодостаточный,
  цитируемый ответ.
- `pricing.md` содержит таблицу пакетов с ценами и сроками (Лендінг $800 / 1–2 тижні,
  Корпоративний сайт $3 500 / 4–8 тижнів, Кастомна платформа $6 000 / 8–16 тижнів) —
  готовый к цитированию блок.

Находка: **раздел llms.txt не содержит ru-версию сайта вообще** — ни `/ru/...` ссылок,
ни `.md`-двойников для ru. Только uk и en. Это усиливает уже известную асимметрию локалей
(vs-wordpress/vs-freelancers/vs-constructors и /support отсутствуют в ru согласно
`_AUDIT-CONTEXT.md`) — ru-локаль лишена даже той AI-инфраструктуры, которая есть у uk/en.

Позиция по ценности llms.txt в целом (без догм): Google официально заявил, что Search
**не использует** llms.txt как сигнал ранжирования — подавать его владельцу как
SEO-фактор для Google было бы нечестно. Для ChatGPT/Perplexity/Claude прямых
доказательств влияния на цитируемость тоже нет — крупные AI-краулеры в первую очередь
читают обычный HTML и sitemap.xml. То, что здесь уже сделано полезно независимо от
llms.txt как «сигнала»: сами markdown-версии страниц дёшево читать любому агенту,
который наткнётся на них по ссылке — это самостоятельная ценность вне вопроса,
«читает» ли их конкретная платформа как манифест.

## 4. Цитируемость на уровне пассажей — по страницам

**Главная** (`parse_html.py` + сырой HTML):
- Хиро-абзац с атрибутом `data-speakable="hero-description"` — самодостаточный блок:
  «За 4–10 тижнів ви отримуєте сайт, який швидко завантажується, викликає довіру з
  першого екрана й ранжується в Google та AI-пошуку. Ваша участь — 5 годин.» Конкретный
  срок + конкретная метрика участия клиента. `data-speakable` — прямой сигнал, что автор
  уже проектировал контент под голосовые/AI-summary сценарии.
- Meta description содержит цену и срок: «Фікс-ціна від $800 ✔️ ... Запуск за 4–10
  тижнів» — цитируемые числа прямо в `<meta name="description">`.

**`/pricing`** (word_count 940, проверено `parse_html.py`):
- FAQ-секция «Часті питання про ціни» реализована через нативные `<details><summary>` —
  5 вопросов, все присутствуют в сыром HTML (не подгружаются по клику через JS):
  «Скільки коштує зробити сайт?», «Що входить у вартість розробки сайту?», «Скільки часу
  займає розробка сайту?», «Чому ви даєте фіксовану ціну, а не «під запит»?» и т.д.
- Подтверждено JSON-LD `FAQPage` schema на странице (плюс `BreadcrumbList`, `WebPage`,
  `Service`) — вопросы из `<summary>` совпадают с `FAQPage`, разметка не расходится с
  видимым контентом.
- Таблица пакетов с ценами (от $800 / $3 500 / $6 000) видна в сыром HTML.

**`/process`** (word_count 1012, проверено `parse_html.py`):
- H3-заголовки — это **не вопросы**, а короткие ярлыки шагов: «Бриф», «Договір і
  передоплата», «Дизайн», «Розробка», «Тестування», «Запуск», «Підтримка». В отличие от
  `/pricing` и `/seo`, здесь вопросно-ответная структура не применена — сравнение
  визуальное (шаги), а не Q&A. Это не ошибка, но упущенная возможность: страница
  объясняет процесс, но не в формате, который легко вырезать LLM как прямой ответ на
  «как проходит проект».

**`/seo`** (проверено через WebFetch, качественно):
- H2/H3 включают реальные вопросы: «Скільки коштує просування сайту?» → «$300/міс.
  E-commerce з каталогом — $500/міс» (прямой ответ первым предложением); «Чому ви не
  гарантуєте топ-1?» → «Бо Google не продає позиції...»; «Коли будуть результати?» →
  «Перші вимірні зміни — за 3–6 місяців». Образцовая структура вопрос→прямой ответ,
  сопоставимая с `/pricing` и `faq.md`.

**`/vs-wordpress`** (проверено через WebFetch):
- Есть секция «Що питають найчастіше» (FAQ) и структурированное сравнение WordPress vs
  Code-Site с конкретными цифрами (например, LCP: WordPress 3–5с против <1с на
  Code-Site; ежемесячные расходы $50–200 vs $0–20). Есть цитируемый кейс: «З 3 заявок на
  місяць вийшли на 24 в перший же місяць» — конкретная цифра-результат клиента.
- Напоминание: страница **отсутствует в ru-локали** (см. `_AUDIT-CONTEXT.md`) — весь этот
  цитируемый сравнительный контент недоступен ru-аудитории и ru-версии LLM-ответов.

**Блог — 2 статьи проверены (`ai-poshuk-yak-potrapyty-u-vidpovidi`,
`lokalne-seo-top-3-google-maps`)**:
- Обе имеют FAQ-секцию с H3-вопросами и прямыми ответами: например, «Скільки часу до
  топ-3 карт?», «Чи можна купити відгуки?», «Чи варто блокувати AI-ботів у robots.txt?».
  Симптоматично, что статья про AI-поиск сама отвечает на вопрос про блокировку
  AI-ботов в robots.txt — стоит свериться, что фактический `robots.txt` сайта не
  противоречит тому, что написано в статье (см. находку №1).
- Есть byline («Крістина Бондаренко, SEO Specialist») и дата публикации («16 сер 2026»)
  на обеих статьях — сигнал авторства и свежести для E-E-A-T.
- Слабое место: числа в статьях («$300–$2 000+/міс», «50+ проєктів за 5 років», «80%
  пацієнтів не гортають далі першої сторінки») **не имеют внешних источников/ссылок** —
  ни одна статья не цитирует внешнее исследование или данные. Для LLM, которые предпочитают
  атрибутируемые данные, это слабее, чем нейтральные тарифные факты на `/pricing` и
  `/seo` (которые являются собственными фактами компании и не нуждаются в источнике).

## 5. Вопросные заголовки (H2/H3) — по разделам сайта

Смешанная картина, не единая политика:
- **Сильно** (реальные вопросы + прямой ответ первым предложением): `/pricing` (FAQ),
  `/seo`, `/vs-wordpress` (FAQ), обе проверенные статьи блога, `faq.md`.
  `/pricing.md` — де-факто чистый Q&A через `.md`.
- **Слабо** (заголовки-ярлыки, не вопросы): `/process` — 7 H3 это одиночные слова-шаги,
  ни одного вопроса.
- Вывод: вопросно-ответный паттерн внедрён осознанно (видно по повторяемости на разных
  типах страниц и по совпадению с FAQPage-схемой), но не покрывает весь сайт равномерно —
  `/process` выпадает из общего паттерна.

## 6. Сигналы бренда и сущности

Из JSON-LD на главной (доступно ботам без JS):
- `Organization` с `@id`, `name: "Code-Site.Art"`, `alternateName`: `["Code-Site Art",
  "CodeSite", "Code Site", "Code-Site.Art", "code-site"]` — явно перечислены варианты
  написания бренда для entity resolution, плюс для LLM, сопоставляющих упоминания в
  разных формах.
- Плотная разметка: `ContactPoint`, `PostalAddress`, `Person`, `Review`, `Rating`,
  `QuantitativeValue`, `Place`, `ImageObject`, `SpeakableSpecification`, `WebSite`,
  `WebPage` — всё в исходном HTML, не требует JS.
- `faq.md` подтверждает конкретные E-E-A-T факты текстом: «Засновник — Федір Алпатов,
  розробник і технічний лід; студію засновано у 2023 році» — именованный основатель,
  дата основания, стек (Next.js, React, TypeScript, Sanity CMS) — конкретные, проверяемые
  утверждения о личности за брендом.
- Внешние упоминания бренда (Wikipedia, Reddit, YouTube, LinkedIn, объём и тональность
  за пределами сайта) — **не перевірено** в этом проходе: требует `commoncrawl_graph.py`
  / `verify_backlinks.py` или ручного веб-поиска, не успел в рамках бюджета. Также
  недоступны живые данные о фактических AI-цитированиях (DataForSEO не подключён,
  согласно `_AUDIT-CONTEXT.md`) — платформенные оценки (Google AIO / ChatGPT /
  Perplexity / Bing Copilot) невозможно посчитать по факту, а не гадать.

## 7. Agent-friendly проверка (`agent_ux_check.py`)

Главная (`https://www.code-site.art/`) — статический HTML-анализ:

```
score: 100/100, issues: []
real_buttons: 11, real_anchors: 83, div_onclick_widgets: 0
semantic_landmarks: 17, inputs_without_aria: 0, inputs_without_label: 0
```

Нет фейковых `div onclick` виджетов, все интерактивные элементы — настоящие `<button>`/
`<a>`, поля форм имеют labels/aria, присутствуют семантические landmarks. Для AI-агента,
который должен понять структуру страницы и совершить целевое действие (например, найти
кнопку заявки), это хороший результат. `a11y_findings.tree_present: false` —
accessibility-дерево не было получено в этом прогоне (скрипт не запускался в режиме
рендера headless-браузера), это отдельно не является находкой, просто ограничение
конкретного запуска.

## 8. Три локали (uk/en/ru) — конкуренция за цитирование

- `hreflang` для uk/en-GB/ru проставлен корректно на главной (`x-default` → uk).
- `llms.txt` — **явно исключает ru** (см. пункт 3): ни ссылок на `/ru/...`, ни
  markdown-двойников для ru-страниц.
- `vs-wordpress / vs-freelancers / vs-constructors` и `/support` отсутствуют в ru
  согласно `_AUDIT-CONTEXT.md` — ru-версия не может дать LLM тот же цитируемый
  сравнительный контент, что uk/en.
- Вывод: конкуренции локалей за один и тот же ответ не выявлено (hreflang корректный,
  контент не дублируется бессмысленно) — наоборот, ru системно **недополучает**
  AI-инфраструктуру по сравнению с uk/en. Риск не «каннибализация», а «невидимость»
  ru-аудитории в AI-поиске.

## Что уже работает хорошо (не находки, для баланса отчёта)

- `llms.txt` присутствует и нетривиален: ссылается на выделенные `.md`-версии
  `/about.md`, `/faq.md`, `/pricing.md` (и en-аналоги) — редкая деталь даже среди
  сайтов, которые в принципе завели `llms.txt`.
- `faq.md` и `pricing.md` — образцовый пример извлекаемых, самодостаточных ответов:
  вопрос → прямой ответ первым предложением → цифра/срок/условие.
- `/pricing` реализует FAQ через `<details><summary>` (контент в DOM без JS) с
  подтверждённой `FAQPage` JSON-LD schema, разметка совпадает с видимым текстом.
- Главная содержит `data-speakable` атрибут на ключевом абзаце — прямой сигнал заботы о

  семантические — сайт агенто-дружелюбен структурно.
- Контент реально доступен ботам без исполнения JS — дорогая находка из ТЗ не

- Статьи блога имеют byline и дату публикации — базовый E-E-A-T на месте.
