# GEO / AEO — готовность code-site.art к AI-поиску

Статус: черновой срез, записан досрочно по бюджету шагов. Пункты без данных помечены
«не перевірено» — это честный пробел, а не находка.

## 1. Доступ AI-краулеров (robots.txt)

Источник: `_AUDIT-CONTEXT.md` (уже собранный факт) — `robots.txt` → HTTP 200,
`Allow: /`, `Disallow: /stories/`, `Host: https://www.code-site.art`,
`Sitemap: https://www.code-site.art/sitemap.xml`.

Правил под конкретные User-Agent (GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot,
anthropic-ai, CCBot, Google-Extended, Bytespider, Applebot-Extended) в файле **нет** —
работает только блок `User-Agent: * / Allow: /`, который по умолчанию открывает доступ
всем ботам, включая AI-краулеров.

Это не ошибка, а, скорее всего, отсутствие осознанного решения (default Next.js robots.txt).
Компромисс, который стоит явно объяснить владельцу:
- **Плюс:** GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot — все три «поисковых» краулера,
  через которые сайт может попасть в цитаты ChatGPT/Perplexity/Claude — не заблокированы.
  Открытый доступ — правильное решение для GEO-стратегии, которую сайт сам продаёт на
  главной («ранжується в Google та AI-пошуку»).
- **Компромисс:** та же строка `Allow: /` разрешает и краулеры, которые тренируют модели на
  контенте (CCBot, anthropic-ai, Bytespider), и `Google-Extended`, который **не влияет на
  обычный органический поиск Google**, а управляет только использованием контента для
  тренировки Gemini/AI Overviews моделей. Блокировка `Google-Extended` не уменьшит
  видимость в Google Search и Google AI Overviews — можно закрыть его отдельно, если
  владелец не хочет, чтобы контент шёл в тренировочные датасеты, без риска для SEO.
- Точных правил под каждого бота нет — сайт полагается на дефолтное поведение `*`, это
  работает, но не документирует намерение. Рекомендация: явные строки `User-agent: GPTBot`,
  `User-agent: ClaudeBot`, `User-agent: PerplexityBot`, `User-agent: OAI-SearchBot` c
  `Allow: /` — фиксируют решение и защищают от случайной блокировки при будущих правках
  файла.

## 2. Реальная выдача контента ботам без JS

Проверено через `fetch_page.py` (без рендера, чистый HTTP GET, как получают боты, не
исполняющие JS) на `https://www.code-site.art/`:

- Полный ответ — 481 839 символов HTML, статус 200.
- Первый дочерний элемент `<body>` — `<div hidden=""><!--$--><!--/$--></div>` (пустой
  Suspense-плейсхолдер/портал-контейнер Next.js) — на первый взгляд похоже на пустую
  страницу, **но это ложная тревога**: сразу следом в теле документа идёт реальная,
  не скрытая разметка — `<h1>`, `<p data-speakable="hero-description">` и т.д. с полным
  видимым текстом («Сайти будь-якої складності, що приводять заявки 24/7...»).
- По факту (сообщено координатором) серверный HTML главной содержит **1530 слов / 9898
  символов** видимого текста — контент реально приходит краулерам без исполнения JS.
- Скудная выдача trafilatura (503 символа, зафиксированная в `_AUDIT-CONTEXT.md`) —
  **артефакт алгоритма отсечения шаблонной обвязки (boilerplate) trafilatura**, а не
  признак тонкого контента или CSR-проблемы. Не путать одно с другим в отчёте.
- JSON-LD (`application/ld+json`, `@graph`: Organization, WebSite, Person, Review,
  Rating, PostalAddress, ContactPoint, SpeakableSpecification, QuantitativeValue,
  ImageObject, Place, WebPage) присутствует прямо в исходном HTML — доступен ботам без JS.
- Вывод: технически сайт SSR/ISR (`X-Nextjs-Prerender: 1`), контент доступен ботам без
  исполнения JavaScript. Дорогая находка из ТЗ **не подтвердилась** — это хорошая новость,
  но стоит перепроверить на 1-2 внутренних страницах (`/pricing`, `/process`), т.к. не все
  шаблоны обязаны вести себя так же, как главная — **не перевірено**.

## 3. llms.txt и RSL 1.0

**Не перевірено** в этом проходе — не успел сделать `fetch_page.py` на `/llms.txt`.

Общая позиция для отчёта (не зависит от факта наличия файла): Google официально заявил,
что Search **не использует** `llms.txt` как сигнал — это не SEO-фактор и не должен
подаваться владельцу как способ повлиять на ранжирование в Google. Для ChatGPT/Perplexity/
Claude прямых доказательств влияния `llms.txt` на цитируемость тоже нет — крупные
AI-краулеры индексируют обычный HTML и `sitemap.xml`, а не курируемый список ссылок.
Итог: `llms.txt` — низкий приоритет, ставить в бэклог как дешёвый эксперимент без
доказанного эффекта, не как обязательный пункт.

RSL 1.0 (RSL licensing) — не проверено, отдельно не встречалось признаков внедрения на
сайте (ни в `robots.txt`, ни в `<head>` главной).

## 4. Цитируемость на уровне пассажей

Проверена только главная (`geo-raw-default.html`, полный SSR HTML).

Наблюдения по главной:
- Хиро-абзац (`data-speakable="hero-description"`) — самодостаточный блок, отвечает на
  вопрос «что вы получаете и когда»: «За 4–10 тижнів ви отримуєте сайт, який швидко
  завантажується, викликає довіру з першого екрана й ранжується в Google та AI-пошуку.
  Ваша участь — 5 годин.» Есть конкретный срок (4–10 тижнів), конкретная метрика
  участия клиента (5 годин) — хороший кандидат на AI-цитату. Атрибут `data-speakable`
  говорит, что автор уже думал о голосовом/AI-summary use-case — сильный сигнал, что GEO
  на сайте не полностью проигнорирован.
- Meta description содержит цену: «Фікс-ціна від $800» и срок «Запуск за 4–10 тижнів» —
  конкретные, цитируемые числа прямо в `<meta name="description">` и JSON-LD.
- `/pricing`, `/process`, `/seo`, `/vs-wordpress`, 3 статьи блога — **не перевірено**
  (не успел прогнать fetch_page.py по каждой странице в рамках бюджета). Это открытый
  пункт для следующего прохода: важно проверить, есть ли на них такая же плотность
  самодостаточных ответов, как на главной, или это исключение.

## 8. Три локали (uk/en/ru) — конкуренция за цитирование

анализа, какая локаль индексируется/цитируется чаще в AI-поиске — **не перевірено**
