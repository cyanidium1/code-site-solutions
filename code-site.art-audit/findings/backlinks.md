# Ссылочный профиль — code-site.art

**Доступный уровень инструментов: Tier 0** (Common Crawl + верификационный краулер + WHOIS).
Ключей Moz, Bing Webmaster нет; DataForSEO не подключён.
→ DA/PA, spam score, полный список доноров, анкор-лист, follow/nofollow-разбивка,
динамика ссылочной массы **недоступны в этом аудите**. Ниже — честный максимум из того,
что можно получить бесплатно, плюс явная граница того, что нельзя.

## Итоговая оценка: INSUFFICIENT DATA (не 0-100)

Из 7 весовых факторов confidence-модели ссылочного здоровья (referring domains, domain
quality distribution, anchor naturalness, toxic ratio, link velocity, follow/nofollow,
geo relevance) на Tier 0 **закрыто фактическими данными 0 из 7** — Common Crawl отдаёт
только агрегированные домен-метрики графа, а не список ссылающихся доменов
(`--top-referrers` в `commoncrawl_graph.py` — заявленный "legacy no-op": скрипт прямо
говорит, что referring domains не извлекаются). Выставлять число 0-100 при таком
покрытии значило бы выдать угадывание за измерение — этого делать не буду. Ниже —
качественная картина с честными оговорками по каждому пункту.

## 1. Что известно достоверно

### 1.1 Common Crawl — граф домена (confidence: 0.50, домен-уровень)

Источник: `commoncrawl_graph.py code-site.art --json`, релиз `cc-main-2026-jan-feb-mar`
(квартальное обновление, https://commoncrawl.org/web-graphs).

| Метрика | Значение | Что это значит | Чего это НЕ значит |
|---|---|---|---|
| `in_crawl` | `true` | Домен физически попал в crawl этого квартала — минимальная видимость есть | Не говорит о качестве или количестве ссылающихся страниц |
| `in_rankings` | `true` | Домен присутствует в ранжированном графе (не отфильтрован как спам/шум) | Не говорит о позиции в поиске Google |
| `pagerank` | `5.214174445668738e-09` | Экспериментальная CC-метрика (не Google PageRank, тот отключён с 2016) по графу связей между хостами | Абсолютное число почти ничего не значит без сравнения — важен только ранг ниже |
| `pagerank_rank` | `15 374 900` | Позиция домена в списке хостов, отсортированных по этой метрике (меньше = «авторитетнее» в графе) | Без знания общего числа хостов в графе нельзя посчитать процентиль — намеренно не считаю его, чтобы не выдумывать цифру |
| `harmonic_centrality` | `13 326 079.0` | Мера «связности» узла в графе (обратное расстояние до других узлов) | Не мера трафика или конверсий |
| `harmonic_centrality_rank` | `9 869 474` | Ранг по связности | Тот же принцип: чем меньше число — тем более «встроен» домен в граф |
| `n_hosts` | `1` | В графе учтён один хост (нет данных о поддоменах с отдельным весом) | — |

**Как читать владельцу:** сайт технически виден краулеру Common Crawl и не выброшен как
спам, но обе ранговые метрики — многомиллионные (глубоко не в топе). Для домена,
зарегистрированного 15 месяцев назад, это ожидаемо и само по себе не тревожный сигнал —
тревожным было бы отсутствие в графе вообще (`in_crawl: false`) или отрицательные
сигналы риска. Ни PageRank, ни harmonic centrality CC не публикует как измерение
для отдельных доноров — это домен-уровень, поэтому нельзя сказать, «сколько доменов
ссылается» по этим цифрам.

`domain_history.py` не делает тематическое сравнение сам, поэтому я догрузил его

  ассеты, редиректы).
- Самый ранний снимок: **2025-07-10** (редиректы 307/308 на `www.code-site.art`, затем
  ассеты сайта — `blue-gradient.png`, `buttonbg-1.png`, узнаваемые по текущей дизайн-
  системе).
- Первый полноценный HTML-снимок с кодом 200: **2026-04-21**.
- Никаких следов другой тематики (нет более ранних снимков до регистрации домена,
  что логично при возрасте 1.31 года) — сайт с первого дня в архиве выглядит как
  текущая веб-студия.

**Вывод:** признаков «унаследованного шлейфа» (expired-domain abuse, QRG §4.6.7) —
**нет**. Это честный плюс: молодой чистый домен без чужого мусорного профиля ссылок.
Оговорка: отсутствие снимков с другой темой — не строгое доказательство (Wayback
не индексирует всё), но при возрасте домена 15 месяцев и совпадении дат регистрации
и первого снимка вероятность скрытой «прошлой жизни» практически нулевая.

Источник: `parasite_risk.py https://www.code-site.art/ --json`.

| Метрика | Значение |
|---|---|
| Проверено страниц | 1 (главная) |
| Third-party hits/page | 0.0 |
| Commerce hits/page | 0.0 |
| Affiliate-link hits/page | 0.0 |
| Флаги | нет |
| Риск | low |

**Важно понимать, что это измеряет и что нет:** этот скрипт смотрит на **исходящие**
сигналы с самой страницы (сторонние виджеты, партнёрки, коммерческая разметка) — это
проверка на «паразитное SEO соседство» по политике репутации сайта Google, а **не**
проверка токсичности входящих бэклинков (для неё нужен реальный список доноров,
которого нет). Кроме того, проверена только главная — не блог, не портфолио, не
`/sites-for/`. Для полной картины стоит прогнать те же 208 URL из `all-urls.txt`,
это не было сделано в этом проходе.

## 2. Явная граница: чего измерить нельзя на Tier 0

| Фактор скоринга | Нужен источник | Статус |
|---|---|---|
| Количество referring domains | DataForSEO / Moz | Нет данных. CC граф не отдаёт список доноров (`--top-referrers` — явный no-op) |
| Распределение качества доноров (DA/DR) | DataForSEO / Moz DA | Нет данных |
| Естественность анкор-текста | DataForSEO / Moz / Bing anchors | Нет данных |
| Доля токсичных ссылок | DataForSEO / Moz Spam Score / verify-краулер | Нет данных — нечего верифицировать без списка доноров |
| Динамика ссылочной массы (velocity) | Только DataForSEO | Нет данных |
| Follow/nofollow-разбивка | DataForSEO / Bing link details | Нет данных |
| Гео-релевантность доноров | DataForSEO / Bing country data | Нет данных |

**`verify_backlinks.py` не запускался** — скрипту нужен файл-список кандидатов
(`--links`, формат `[{"source_url": "..."}]`), а такого списка нет ни от пользователя,
ни от Common Crawl (граф не отдаёт индивидуальные ссылки, только агрегаты), ни от
Moz/DataForSEO (недоступны). Как только появится любой реальный список (например,
через Google Search Console → отчёт «Ссылки», если/когда будет доступ к GSC — по
контексту аудита сейчас нет и туда, tier -1), эту проверку нужно прогнать первой.

**WebSearch по упоминаниям бренда — не выполнен достоверно.** В этой суб-агентной
сессии нет привязанного инструмента веб-поиска. Я предпринял резервные попытки через
`curl` к публичным поисковикам и получил только доказательства блокировки/ненадёжности,
а не результаты:

- Google: `curl` вернул `302 → /sorry/index` (CAPTCHA-стена для автоматических
  запросов) — ответа по существу нет.
- DuckDuckGo HTML (`html.duckduckgo.com/html/`): вернул anomaly-challenge страницу
  вместо результатов.
- Bing: страница отдалась, но точные кавычки `"code-site.art"` были молча
  проигнорированы — в выдаче оказались нерелевантные `code.org`, `codecademy.com`,
  `freecodecamp.org` и т.п. (совпадение по словам «code»/«site», не по домену).
  Присваивать это реальным результатам поиска было бы фабрикацией.
- Yandex: пустой ответ (страница требует JS-рендер, `curl` его не получает).

**Вывод: наличие или отсутствие незалинкованных упоминаний бренда не подтверждено
и не опровергнуто** — это открытый вопрос, а не «упоминаний нет». Нужен настоящий
WebSearch-доступ (у оркестратора аудита он, вероятно, есть) со следующими точными
запросами:

```
"code-site.art"
"Code-Site.Art"
"Code-Site" студия -site:code-site.art
"код-сайт.арт" OR "код сайт арт"
site:clutch.co "code-site.art" OR "Code-Site.Art"
```

## 4. Стратегия наращивания ссылочной массы — ниша веб-разработки

Контекст: молодая веб-студия (домен 15 мес.), заявленная география UA, EU, US, DK, ZA,
UK, FR. При нулевом обнаруживаемом ссылочном профиле приоритет — не гостевой питчинг
в топ-издания (нереалистично при текущем DR), а быстрые, реалистичные и белые источники
первых 15-30 доменов.

### 4.1 Самый дешёвый источник — уже выполненные проекты
26 кейсов в портфолио (`portfolio`, по 26 на каждую локаль по данным `_AUDIT-CONTEXT.md`)
— потенциальные доноры, если у клиентских сайтов в футере есть или можно согласовать
кредит-ссылку («Website by Code-Site.Art» / «Розробка сайту — Code-Site.Art»). Это не
было проверено в этом прогоне (нужен список живых URL клиентов и `verify_backlinks.py`
по нему) — рекомендую как первое конкретное действие: собрать URL всех 26 клиентских
сайтов из карточек портфолио и прогнать через verify_backlinks.py, затем для тех, у
кого кредит-ссылки нет, — согласовать её с клиентом.

### 4.2 Агентские каталоги и маркетплейсы (EN/международные, релевантны для EU/US/UK/DK/ZA-гео)
- **Clutch.co** — профиль + верифицированные отзывы клиентов (нужен реальный клиент,
  готовый пройти верификацию по звонку); самый весомый сигнал доверия в нише
- **The Manifest** (сестринский проект Clutch) — порог ниже, тот же профиль можно
  синхронизировать
- **GoodFirms** — бесплатный профиль со ссылкой на сайт
- **DesignRush** — каталог агентств, есть бесплатный тир
- **Sortlist** — маркетплейс агентств с фокусом на EU (хорошо ложится на DK/UK/FR-гео)
- **TopDevelopers.co**
- **Crunchbase** — карточка компании (nofollow, но это авторитетная бизнес-цитата,
  часто используется как источник другими каталогами)

### 4.3 Дизайн-шоукейсы (портфолио-ссылки под конкретные кейсы, не общий профиль)
- **Awwwards** — платная подача (~$14-19/сайт), при отборе даёт контекстную ссылку
  с очень сильной дизайн-репутацией страницы
- **CSS Design Awards / CSSWinner**
- **Land-book**, **SiteInspire**, **One Page Love** — бесплатные/недорогие галереи
- **Behance**, **Dribbble** — кейс-проект с ссылкой на code-site.art в описании
  (в основном nofollow, но сильный реферальный трафик и часто сами ранжируются в
  поиске по имени бренда)

### 4.4 UA-рынок (студия физически базируется в Украине)
- **DOU.ua → dou.ua/companies** — карточка компании в крупнейшем украинском
  IT-комьюнити, ссылка на сайт + возможность публиковать статьи в блоге компании
  (реальный дофоллоу-потенциал и профильная аудитория именно заказчиков веб-разработки)
- **Djinni.co** — карточка компании-работодателя, ссылка на сайт
- **AIN.UA** — украинское техно-медиа, питчинг кейсов/пресс-релизов о завершённых
  проектах
- Региональные IT-кластеры (**Lviv IT Cluster**, **IT Ukraine Association**,
  **IT Cluster Kharkiv** и т.п.) — членство даёт строчку в публичном каталоге
  участников со ссылкой; требует уточнить, состоит ли студия в одном из них

### 4.5 RU-язычный сегмент (сайт имеет `ru`-локаль — 64 URL по карте сайта)
- **Habr.com** — крупнейшее СНГ-комьюнити разработчиков, статьи с профилем автора
  и потенциальными ссылками в теле поста при реальной технической ценности контента
- **Tagline.ru** — рейтинг digital-студий и премия, профиль студии
- **Cossa.ru**, **VC.ru** — медиа для питчинга кейсов/экспертных колонок

  *Оговорка:* в `_AUDIT-CONTEXT.md` уже зафиксирована асимметрия — разделы
  `vs-wordpress/vs-freelancers/vs-constructors` у `ru`-локали **нет** (в отличие от
  `ua` и `en`). Это сигнал, что приоритет `ru`-рынка для владельца, возможно, ниже —
  прежде чем вкладываться в RU-площадки, стоит явно уточнить у владельца, целевой ли
  это рынок вообще (вопрос уже поднимался в предыдущих сессиях аудита, см.
  `seo-strategy-answers.md` в памяти — при выполнении этой ветки уточнить состояние
  решения).

### 4.6 Универсальные B2B-цитаты (низкий порог входа, вес как трастовые NAP-сигналы)
- **Google Business Profile** — не бэклинк в чистом виде, но фундаментальная
  цитата+ссылка
- **Europages** — B2B-каталог с сильным покрытием EU (соответствует DK/UK/FR-гео)
- **Kompass.com**
- **Connectively (ex-HARO)** — запросы от журналистов, экспертные комментарии по
  веб-разработке дают редакционные (не платные) ссылки в реальных изданиях

### Что не рекомендую
Массовая закупка ссылок, PBN, автоматические каталоги-«простыни» без модерации —
при текущем нулевом профиле и малом трасте риск переоптимизации/токсичного профиля
выше пользы, а перепроверить токсичность на Tier 0 всё равно нельзя (см. п.2) —
значит, любая агрессивная схема останется невидимой для собственного мониторинга
владельца до появления Moz/DataForSEO.
