# code-site.art — Technical + On-Page SEO Audit

Дата: 2026-08-23. Источник истины — живой сайт `https://www.code-site.art` (прод на Vercel/Next.js 15,
App Router, next-intl). Все 208 URL из `all-urls.txt` прочитаны напрямую (без API GSC/PSI/CrUX —
их нет, tier -1, см. `_AUDIT-CONTEXT.md`). Методология: `sitemap_discovery.py`, ручные `curl`-прогоны
редиректов/заголовков, и python-краулер по всем 208 URL (5 потоков) с разбором `<title>`,
`<meta description>`, canonical, robots meta, `X-Robots-Tag`, H1, hreflang (HTML `<head>`), og:locale,
`html lang`, внутренних ссылок — плюс отдельный XML-парсер трёх sitemap-карт для hreflang-реципрокности.

## Раздел A — Technical SEO

### A.1 Редиректы

- `http://code-site.art` (без www, без https) → **2 хопа**: `http://code-site.art` →308→
  `https://code-site.art/` →308→ `https://www.code-site.art/`. Это цепочка длиннее одного хопа —
  находка (см. ниже).
- `https://code-site.art` (без www) → 308 → `https://www.code-site.art/` — 1 хоп, ок.
- `http://www.code-site.art` → 308 → `https://www.code-site.art/` — 1 хоп, ок.
- Слэш на подстраницах: `/about/` → 308 → `/about` (без слэша) — канонично, 1 хоп. Проверено также на
  `/en/` → 308 → `/en`, `/portfolio/` → 308 → `/portfolio`.
- `/index` → **200 напрямую, НЕ редиректит** на `/`. Контент побайтово идентичен `/` (504875 байт,
  тот же `<title>`), `X-Matched-Path: /` в заголовке — Vercel отдаёт prerendered `index`-файл как алиас
  корня. Canonical на `/index` корректно указывает на `https://www.code-site.art` (не на `/index`),
  поэтому индексации дубля не будет, но URL остаётся отдельной живой точкой входа без явного редиректа.
- `/index.html` → 404 (не алиасится).
- Все 208 URL из sitemap при прямом обращении отдают 200 **без единого редиректа** (`num_redirects=0`
  для всех 208 в краулере) — carte hygiene хорошая, в sitemap нет редиректных URL.
- `/stories/` → 308 → `/stories` → **404**. Путь закрыт в robots.txt (`Disallow: /stories/`), но физически
  не существует (404) и нигде не залинкован внутри сайта (0 совпадений `stories` среди ссылок,
  собранных с 208 краулированных страниц). Правило в robots.txt — мёртвый груз, не вредит, но
  бессмысленно.

### A.2 Индексируемость

- **robots meta**: 0 из 208 URL сайта содержат `noindex` — проверено на полном множестве, не на выборке.
  Случайных noindex не найдено.
- **`X-Robots-Tag`**: заголовок отсутствует на всех 208 проверенных ответах (ни noindex, ни прочих
  директив) — согласуется с meta robots, никакого конфликта header vs meta.
- `robots.txt` → 200, валиден: `Allow: /`, `Disallow: /stories/`, `Host: https://www.code-site.art`,
  `Sitemap: https://www.code-site.art/sitemap.xml`.
- `sitemap_discovery.py --json` подтвердил валидность через объявление в robots.txt (`declared` +
  `found` совпадают, `valid: true`, `kind: sitemapindex`) — это не протухшая декларация, реальный файл
  на месте.
- Юридические страницы `/public-contract`, `/policy`, `/legal`, `/offer`, `/cookies` — все `200`,
  корректно `<meta name="robots" content="noindex, nofollow">`, самореференсный canonical, **не входят**
  в sitemap. Это правильная практика (боилерплейт вне индекса), не находка.

### A.4 Hreflang (приоритет)

Источники: XML трёх sitemap-карт (271/271/256 `xhtml:link` записей на ua/en/ru) + HTML `<head>` всех
208 живых страниц.

**Что работает:**
- Коды языков корректны: `uk` (не ошибочное `ua`), `en-GB`, `ru`, `x-default` — других значений нет.
- Реципрокность: **0 нарушений** среди пар, где alternates вообще заданы — если A→B, то у B всегда
  есть обратная ссылка B→A с верным кодом.
- Битых hreflang-целей (href, которого нет ни в одной карте): **0**.
- 192 из 208 URL (92%) несут полный 3-язычный кластер (uk + en-GB + ru + x-default, 4 тега) —
  совпадает между sitemap и HTML один в один.

**Критическая находка — 6 URL с НУЛЕВЫМ hreflang-блоком** (ни self-reference, ни x-default, ни в
sitemap, ни местами в HTML):
- `/support` (ua)
- `/sites-for/medicine/stomatolohiia` (ua)
- `/sites-for/medicine/medychnyi-tsentr` (ua)
- `/blog/shcho-vkhodyt-u-vartist-rozrobky-saitu` (ua, lastmod 2026-08-22 — свежий пост)
- `/en/blog/web-design-for-accountants` (en, lastmod 2026-08-22)
- `/en/blog/websites-for-solicitors` (en, lastmod 2026-08-22)

Первопричина — `src/lib/server/sitemap-data.ts`, функция `push()` (~строки 127–147):
```
const hasLocalized = Object.values(localizedUrls).some(Boolean);
if (!hasLocalized) {
  out[DEFAULT_LOCALE].push({ url: uaUrl, ...meta });   // <- alternates вообще не задаётся
  return;
}
```
Когда у страницы нет ни одной кросс-локальной версии, `alternates` не выставляется совсем —
не только межъязыковые ссылки, но и **self-reference и x-default тоже пропадают**. Для блог-постов
аналогичная логика на ~строках 190–208 (пост только одной локали пушится без `alternates`).

Проверка живого HTML подтвердила **два разных подслучая одного бага**:
- `/support` и `/sites-for/medicine/stomatolohiia` (и, по паттерну распределения, `medychnyi-tsentr`)
  в HTML `<head>` **имеют** `hreflang="uk"` + `x-default` (2 тега) — их отдаёт другой код (генератор
  метаданных страницы), но sitemap для этих же URL несёт 0 тегов. Т.е. **sitemap.xml расходится с
  живым HTML** для этих 3 URL — разные источники правды в кодовой базе.
- 3 блог-поста (`shcho-vkhodyt-u-vartist-rozrobky-saitu`, `web-design-for-accountants`,
  `websites-for-solicitors`) не имеют hreflang **нигде** — ни в sitemap, ни в HTML `<head>`
  (проверено `curl` — есть только `<link rel="canonical">`, alternate-тегов нет вовсе).

**High — асимметричные 2-язычные кластеры без ru (10 URL, 5 пар uk+en):**
`/about`, `/pricing`, `/vs-wordpress`, `/vs-freelancers`, `/vs-constructors` — каждая пара несёт
`uk` + `en-GB` + `x-default` (3 тега), ru-альтернативы нет. Проверено вживую: `/ru/about`,
`/ru/pricing`, `/ru/vs-wordpress`, `/ru/vs-freelancers`, `/ru/vs-constructors`, `/ru/support` —
все **404**. Формально это не баг hreflang (нельзя ссылаться на несуществующую страницу), но это
прямое следствие асимметрии локалей из контекста аудита: ru-кластер лишён базовых страниц
(«about», «pricing», сравнительных лендингов), из-за чего у ru-пользователя нет hreflang-пути в эти
темы вообще, и общий hreflang-граф сайта фрагментирован на 3-язычное ядро (92%) + урезанные 2-язычные
острова (5%) + полностью изолированные страницы без hreflang (3%).

**x-default**: присутствует на всех URL, где вообще есть alternates-блок (202/208); отсутствует ровно
на тех же 6 URL с нулевым блоком — тот же баг, не отдельная проблема.

## Раздел B — On-Page SEO

### B.1 `<title>` (208 URL)

- Отсутствующих: 0.
- Дубликатов: **0 из 208** — полная уникальность по всему сайту, три локали не путаются между собой.
- Длина: только 1 выброс за пределы 30–65 символов — `/en/blog/local-seo-google-maps-top-3`, 66 символов
  (`"How to Get Into Google Maps' Top-3: Local SEO | Code-Site.Art"`), фактически на границе, не критично.
- Виден единообразный шаблон `... | Code-Site.Art` без штампованности (сами тайтлы разные).

### B.2 `<meta description>` (208 URL)

- Отсутствующих: 0.
- Дубликатов: **0 из 208** — полная уникальность, включая между локалями.
- Длина вне диапазона 70–160 символов: **39 из 208 (19%)**, все — превышение (до 175 символов), т.е.
  будут обрезаны в сниппете выдачи. Примеры (полный список длиннее, см. лог краулера):
  `/en` (167), `/ru` (164), `/landing`-соседние портфолио-страницы (`portfolio/bravo`,
  `portfolio/kondor-device`, `en/portfolio/*`, `ru/portfolio/*` — почти весь портфолио-шаблон),
  несколько блог-постов (`en/blog/web-design-trends-2026-to-ignore` — 175, `ru/blog/skolko-stoit-sayt-2026` — 165),
  `sites-for/medicine/stomatolohiia` (163), `/ru/seo` (163). Похоже на системную проблему шаблона
  портфолио/про-локали, а не единичные случаи.

### B.3 Структура заголовков

- H1: **ровно 1 на каждой из 208 страниц**, 0 страниц без H1, 0 страниц с множественными H1 — чисто.

### B.4 Внутренняя перелинковка

Построен граф по ссылкам, собранным краулером со всех 208 страниц (`<a href="/...">`, приведено к
абсолютным URL в рамках `https://www.code-site.art`):
- **Сирот: 0** — каждая из 208 sitemap-страниц имеет хотя бы одну входящую внутреннюю ссылку с другой
  краулированной страницы.
- Глубина клика от главной: depth 0 = 1 (главная), depth 1 = 28, depth 2 = 91, depth 3 = 88, макс.
  глубина — 3, недостижимых страниц — 0. Архитектура достаточно плоская.
- Самые глубокие (depth 3) — почти исключительно портфолио- и блог-страницы `/en/*` и `/ru/*`
  (например `en/portfolio/raul-avto`, `ru/blog/ai-poisk-kak-popast-v-otvety`) — логично, они на 3
  уровня вниз от корня через `/en` или `/ru` → `/portfolio` или `/blog` → карточка.
- Все страницы имеют более 1 входящей ссылки (после исключения главной) — распределение анкоров не
  вырождено в единственную ссылку.
- Футер: `/public-contract`, `/policy`, `/legal`, `/offer`, `/cookies` залинкованы с каждой из 208
  страниц (208 вхождений каждая) — ожидаемо для футера, корректно `nofollow` + `noindex` (см. A.2).
- Ссылок на `/stories/` не найдено нигде — см. A.1/A.7.
- Анкор-тексты по конкретным словам не анализировались (не было времени) — **требует отдельной
  проверки**, если нужен разбор точных формулировок анкоров.

### B.5 Open Graph / Twitter

- `og:locale` присутствует на всех 208 URL, 0 несовпадений с локалью URL: `uk_UA` × 73 (корень),
  `en_GB` × 71 (`/en/*`), `ru_UA` × 64 (`/ru/*`). Обратите внимание: ru-локаль использует `ru_UA`
  (русский язык, регион Украина), а не `ru_RU` — вероятно осознанный выбор под ru-говорящую аудиторию
  вне РФ (гео сайта: UA/EU/US/DK/ZA/UK/FR), но стоит подтвердить, что это намеренно, а не копипаста
  `uk_UA`→`ru_UA`.
- `html lang`: 100% совпадение с локалью (`uk`/`en`/`ru`), 0 ошибок на 208 URL.
- `og:title` присутствует, не проверялся на длину/дубликаты отдельно от `<title>` — не было времени.
- `twitter:card` и полнота Twitter-тегов не проверялись — **требует отдельной проверки**.
- Структурированные данные (JSON-LD) проверены только на главной: валидный блок с типами
  `Organization, WebSite, WebPage, Person, Place, PostalAddress, ContactPoint, ImageObject,
  QuantitativeValue, Rating, Review, SpeakableSpecification` — не проверялось на страницах портфолио/
  блога (ожидаются `Article`/`CreativeWork` схемы) — **требует отдельной проверки**.
- Контекст упоминал подозрительно короткий `extracted_text` на главной (503 символа через trafilatura).
  Проверка: это не тонкий контент, а особенность вёрстки — главная построена на коротких
  hero-формулировках, бейджах доверия (гео UA·EU·US·DK·ZA·UK·FR) и карточках, а не на длинных абзацах;
  сам текст осмысленный маркетинговый оффер. Тем не менее для тематической релевантности стоило бы
  добавить на главную дополнительный блок читаемой прозы (Low/Medium рекомендация, не баг).
